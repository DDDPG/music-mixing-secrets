## 每次如何选择

先读整篇内容与全部视觉素材，再按内容形态看目录。初筛 2–3 个候选，读取固定提交下的完整 DESIGN.md，比较：

1. 解释形式：真实界面、信号路由、数据对照、故事叙述，谁是主角？
2. 密度：是否能在手机上读清，而不删掉关键条件？
3. 图片：真实截图放进来是否自然，能否不改 UI 原色就融入？
4. 语气：适合严谨教学、产品演示还是音乐文化？
5. 可执行性：字体许可、图形重排、静态导出是否可靠？

选一个主风格，写一句与内容有关的理由；没有明显胜出的风格则用 Apple。整套可有不同构图，但不混搭多个品牌色与字体体系。README 的一句话只用于检索，不能代替读原文。已发现当前 README 对 ElevenLabs 的描述偏深色，而固定提交的 DESIGN.md 实为浅灰白、暖黑与轻盈编辑风格；应以后者为依据。

## 已保留的候选原文

- apple：真实产品主体、黑白/浅灰底、克制蓝色、低装饰。适合单一概念、产品识别、清晰解释；也是无更佳匹配时的默认。
- linear.app：近黑背景、细线与淡紫强调、软件截图占主位。适合暗色插件界面主导的功能演示；不能因为截图暗就牺牲正文可读性。
- ibm：方正平面、严谨网格、蓝色强调。适合路由、参数关系和结构化技术对照；不照搬企业网页的高信息密度。
- elevenlabs：浅色编辑布局、暖黑字色、轻字体与摄影氛围。适合声音体验与人物叙述；不自动适用于密集的混音知识图。
- notion：此版本含深蓝 hero、紫色主色与多彩功能面板，并非一律黑白。仅在知识组织/分类结构确实受益时考虑。
- spotify：近黑底、绿色、音乐内容主导。适合唱片、歌单或听感文化；混音理论不应仅因“音乐”标签套播放器皮肤。

其他主题可从完整索引挑选并抓取对应文件，无须限制在这六个候选。

## Apple 原文与本项目适配的边界

原文可取用的参考：
- canvas #ffffff；canvas-parchment #f5f5f7；ink #1d1d1f；primary #0066cc；surface-tile-1 #272729；primary-on-dark #2997ff。
- 真实图片为主体，界面装饰后退；字体层级清楚；标题偏 600 字重；正文采用足够行距；不同内容区可通过明暗变化分隔。
- 少量圆角有特定用途；不要到处加药丸框、阴影与渐变。

静态社交图文必须主动改写的部分：
- 原文 17px 正文属于网页 CSS，不能用作 1080×1440 图片中的正文尺寸。本项目保留画布/安全线标准，正文优先 36–44px，需通过 360px 手机预览。
- 中文字距、行高按实际字体和阅读检查决定，不机械套英文字体参数。
- 蓝色可用于解释重点，这是图文适配；原文把蓝色主要定义为交互信号。不要把本项目新规则冒充原品牌规范。
- 删除无意义导航、购买按钮、悬浮条与交互动画；静态页面只保留对读者有用的结构。
- 引用 Apple 是风格参照，不复制官网页面、品牌专有图形或 logo，不暗示官方背书。字体须有实际许可；不默认分发 SF Pro。
- 多数据序列可为区分增加颜色/线型，正文/证据/图例可读性高于单色规则。所有偏离写入本次 design-decision.md。

## 优先级与质量关口

内容正确与手机可读性 > 选定设计 tokens > 导出模板。

素材不能为了风格被改成失真的颜色、形状或界面；关键条件不能为了留白而删除；解释图不能被压成不读标签的装饰。每页可以是放大界面、流程图、时间轴或对照，统一来自字体、色彩和节奏，而不是八页重复同一框架。
